# Research evidence

For an experiment, record the question and hypothesis, dataset and split/version, preprocessing, baseline and configuration, code revision (including uncommitted changes when relevant), environment, random seeds where applicable, execution command, output locations and resource budget. Adapt to the field and retain the information needed to reproduce or interpret the result. Distinguish a planned run, launched run, completed run, and checked result.

Define metrics and aggregation, units, masks, exclusions and comparison conditions. Verify that labels, splits, preprocessing and evaluation match the claim. Track known confounders and changes between runs. When an experiment fails, preserve the failure and logs; do not turn a partial run into a result. A single run or a test on a subset supports only the corresponding limited claim.

Before a conclusion or handoff, link the claim to its actual result artifacts and conditions, note missing baselines or uncertainty, and identify what observation would change the decision. Reopen affected conclusions when data, code, evaluation, or a requirement changes. Never fabricate measurements, references, runs or reproducibility.
